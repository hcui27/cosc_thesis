## Provenance of seed_v1 (fetched 2026-10-26)
- The Component Gallery, https://component.gallery/components/ : 60 components with alternate names and example counts (`component_gallery.csv`).
- Open UI Component Name Matrix, https://open-ui.org/research/component-matrix : component names per design system (`openui_matrix.csv`, 22 systems incl. WAI-ARIA and the HTML platform; browser-engine duplicates dropped). Names were normalised to Component Gallery names with synonyms (a manual map); names used by only 1-2 systems and not matched were dropped (170); 6 used by 3+ systems were kept as `openui_only`.
- Tailwind Plus marketing sections (`tailwind_plus_marketing.csv`): the category names come from search-result summaries, because tailwindcss.com/plus/ui-blocks/marketing is behind a login; check against the live page if you have access.
Caveats: the Component Gallery is one curator's selection; Open UI's matrix is not exhaustive; both are design-system component lists, so they cover widgets well and page-level composition and styling poorly; the normalisation map is hand-made and unreviewed.

## Seed list v1.2 and why these four sources (written 2026-11-02)
`seed_v1_2.csv` (96 items) = v1.1 (82 items with 3 duplicate names merged: `merges_v1_1.csv`, `seed_v1_1.csv`) + public CSS framework vocabularies (`v1_direct_sources/css_frameworks.csv`, built by `build_seed_v1_2.py`). Nothing is removed.

**What the seed list is for.** It is an external, closed vocabulary of web UI features, fixed before looking at our data, against which we test whether the judges' observations (and the codebook they produce) corroborate named features. For that job a source must (1) exist independently of our 28 pages and of any LLM, (2) be a citable, versioned list of names, (3) name things a page can be observed to have, and (4) cover a different part of the space from the other sources. The four sources were chosen to meet those four tests together; none is sufficient alone.

| Source | What it contributes | Why it belongs | What it misses |
|---|---|---|---|
| **The Component Gallery** (60 components, alternate names) | Breadth of widget-level components, with the synonym sets practitioners really use (Accordion = Collapse, Disclosure, Expander...). | Curated by one practitioner from real design systems; names come with usage counts across systems; the alternate names let a judge's wording match a seed item. | One curator's selection; mostly widgets; weak on page-level composition and visual styling. |
| **Open UI Component Name Matrix** (22 systems incl. WAI-ARIA and the HTML platform) | Cross-system agreement: which names several independent design systems share (we keep names used by 3+ systems), plus the platform's own roles. | Gives a consensus filter that does not depend on one curator, and ties names to standards (ARIA, HTML), which is the vocabulary the generated markup actually uses. | Not exhaustive; naming varies between systems; weak on page sections and styling. |
| **Tailwind Plus marketing sections** (16 page-section categories) | Page-level composition: Hero, Pricing, Testimonials, FAQs, CTA, Team, Logo clouds. | The 28 pages are marketing and information sites, so section structure is a major part of what judges describe; the two component lists above hardly name sections. It is the only source here for this level. | Names come from search summaries because the live page is login-gated; one vendor's taxonomy; commercial catalogue. |
| **Public CSS frameworks (Bootstrap 5.3, Bulma, Foundation 6)** | The vocabulary of class and component names that front-end code actually uses (navbar, jumbotron, media object, close button, container, list group). Kept only where at least 2 of the 3 frameworks document the concept. | The generated pages are hand-written HTML/CSS: the agent's own class names come from this shared web-development vocabulary, so framework names are the closest external source to how the generated code itself is organised. They add layout containers and structural pieces (Container, Media object, Menu, Close button) that design-system galleries omit, and their alternate names (Notification, Callout, Navbar, Top Bar) widen matching.  | Documentation navigation, not usage data; three frameworks only; dominated by widgets; naming reflects their own conventions. |

**Why a combination.** Component-level (Component Gallery, Open UI), section-level (Tailwind Plus) and code-vocabulary-level (CSS frameworks) lists answer different "is X on the page?" questions; together they span widgets, page composition and layout/markup vocabulary. Open UI's 3+ systems rule acts as a consensus check on the single-curator and single-vendor lists; the CSS framework list is deliberately exhaustive instead. None of the four is derived from our pages, so the later comparison (how many seed items the judges corroborate vs how many attributes our own codebook adds that the seed lacks) is not circular.

**What the four together still do not cover.** Visual styling (typography, color, spacing, decoration, imagery treatment, copy style) is largely absent from all of them. That is expected: the pilot asks how much of the codebook is "not in any public vocabulary", and those styling attributes are the likely answer. Class names harvested from our own 28 pages were considered and rejected as a source because they would make the seed list depend on the data it is later compared with.

**Known weaknesses to state in the thesis.** All four are design/engineering catalogues, so they over-represent interactive widgets that static marketing pages rarely use (most never-mentioned items are widgets); the normalisation map and the included/excluded calls on the framework lists are hand-made choices; with no consensus filter, single-framework items (e.g. Level, Box, Scrollspy) are in; the framework lists come from navigation pages fetched on 2026-11-02, not from a corpus of real usage.

## Seed list v1.3 (2026-11-04): adds the NN/g UI elements glossary
`seed_v1_3.csv` (120 items) = v1.2 + every term in the Nielsen Norman Group "UI Elements Glossary" (https://www.nngroup.com/articles/ui-elements-glossary/; 61 terms, names and synonyms only, no definitions; `v1_direct_sources/nngroup_glossary.csv`, built by `build_seed_v1_3.py`). No threshold: 37 terms attach to existing items as alternate names (`nngroup` added to their sources) and 24 are new items (e.g. Anchor Link, Back-to-Top Button, Bottom Sheet, Contextual Menu, Floating Button, Megamenu, Menu Bar, Scrollbar, Split Button, Submenu, Lightbox).
Why this source: it is the one practitioner glossary written from usability research on how people see and use interface elements, so it names menus, overlays, feedback and input controls in user-facing terms that complement the component-library (Component Gallery, Open UI), page-section (Tailwind Plus) and code-vocabulary (CSS frameworks) lists. Weaknesses: single publisher, alphabetical with no official categories (any grouping is ours), skewed to interactive controls and to mobile/app patterns, and four entries (Control, Input control, Overlay, Picker) are umbrella terms rather than observable features.
Run with `--seed v1_3` (seed_pilot.py, compare_seed_vs_codebook.py); results go to `*_v1_3` files.
